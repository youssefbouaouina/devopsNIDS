 2. TRIVY - SCA (Java libraries), IaC, CONTAINER IMAGE   (Phase 1)
    Wrapper: security/trivy.sh   Accepted risks: .trivyignore
    Jenkins stages: "SCA + IaC Scan (Trivy)", "Container Scan (Trivy)"
=====================================================================

 A) RUN IT LIVE  (as the jenkins user, inside the Jenkins workspace)
    NOTE: target/ (the jar) exists only when no build is running "mvn clean".
          If you get "lstat target: no such file", wait for the build to pass
          the Package stage, or run the IMAGE scan below (always works).
[VM]  sudo -iu jenkins
[VM]  cd /var/lib/jenkins/workspace/student-management && export WORKSPACE=$PWD

      # SCA: vulnerabilities in every library inside the jar
[VM]  bash security/trivy.sh rootfs --scanners vuln target/
      # IaC: misconfigurations in Dockerfile + Kubernetes manifests
[VM]  bash security/trivy.sh config --skip-dirs lab1-evidence,lab-instructions,reports .
      # Image: OS packages + libraries in the built image
[VM]  bash security/trivy.sh image --scanners vuln youssefbouaouina82/student-management:latest
      # Only HIGH and CRITICAL
[VM]  bash security/trivy.sh image --severity HIGH,CRITICAL youssefbouaouina82/student-management:latest
[VM]  exit                                       # back to vagrant user

 B) ADD A RULE
   1. Accept a risk (vulnerability or IaC check) -> add a line to .trivyignore:
        # why it is accepted + review date
        CVE-2026-XXXXX exp:2027-01-31
        AVD-DS-0026                     # IaC: "no HEALTHCHECK in Dockerfile" (k8s probes cover it)
   2. Make the gate stricter (fail on HIGH too) -> Jenkinsfile, stage "SCA + IaC Scan":
        --severity CRITICAL   ->   --severity HIGH,CRITICAL
   3. Fix an IaC finding (example: MySQL without resource limits) -> k8s/mysql.yaml,
      under the mysql container:
            resources:
              requests: { cpu: 250m, memory: 512Mi }
              limits:   { cpu: "1",  memory: 1Gi }

 C) APPLY / TEST
[VM]  (re-run the matching command from A: the finding disappears)
      commit + push -> next Jenkins build uses it.

   -> [VM] kubectl -n devops get pods ; sudo systemctl restart spring-app-forward
 Prometheus target DOWN
   -> app not deployed yet, or forward down (same as above)
 pre-commit: command not found
   -> ~/.local/bin/pre-commit   (or: pipx ensurepath && source ~/.bashrc)

   -> show build #15 in Jenkins (all green) and docs/evidence/build-15/
